## Changes

- Preserve recovered kitchen supplier/catalog, moodboard editor/recovery, scene and review integration.
- Pack largest panels first and return individually identified physical panels with matching placement metadata, without changing source inputs.
- One exact-project/exact-scene review loader supplies production snapshot, CSV, XLSX, labels, nesting and production PDF paths. Drafts remain available. `intent=released` requires exact unique part IDs, fabrication rules version and SHA-256 fingerprint of panel facts, hardware and rules. A changed dimension/material cannot reuse a review merely because IDs remain unchanged. Unavailable review storage returns an error.
- Persist the fingerprint on review. Existing reviews without a fingerprint must be reviewed again. UI downloads use server authority and explicitly report draft/reviewed status; CSV no longer exports browser-edited rows as factory data.
- Production PDF status follows manufacturing review. Missing laminate sheet count is null, and the handover text no longer automatically authorizes CNC cutting.
- Python exporter preserves mounting height, avoids invented centre divisions, rejects invalid vertical/width geometry and escapes SVG text/attributes.
- Secret scanning skips binary files before decoding, while retaining all text-source scanning.

## Remaining acceptance and roadmap

This is an application integration release, not workshop certification. The supplied sample PDFs are illustrative requirements and cannot establish actual panel counts, yields, certified geometry or zero waste.

Next priorities remain separate face-A/face-B substrate/laminate recipes, supplier stock and offcut profiles, persisted validated nesting/cut sequence, machine-readable QR labels, project-wide exact-room dossier manifests and broader certified furniture recipes. Textual scan IDs are not QR codes. No optimality or zero-waste guarantee is made.

Two-user authenticated hosted acceptance, paid render-provider fidelity, physical label calibration, actual workshop assembly and machine dry-run remain unverified. Native Python worker changes are not deployed as a separate worker service. No new paid services or paid AI calls were introduced.
